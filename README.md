Codabar Lensは、写真に写ったNW-7（Codabar）の番号や記号を端末内で読み取るツールです。
PostMirrorのNW-7機能を切り出し、配色・タブ・4回のタップによる範囲指定・日英切り替え・ダーク表示を引き継ぎました。

## ✨ 機能

- **画像点検**：JPEG・PNG・WebPを読み込み、全体と拡大表示で左右の端を選択
- **読み取り結果**：内容と開始・終了記号を別々に表示。戻る・範囲の選び直し・画像の消去
- **座学**：幅による符号化、文字集合、開始・終了記号、チェック用文字、読み取りの限界
- **共通操作**：日本語・英語、ライト・ダーク表示、タブの矢印・Home・End操作

5タブで「サンプルを読む→画像を加工して比べる→自分の画像を点検する→仕組みを学ぶ→理解を確かめる」と進めます。

| タブ | 内容 |
|---|---|
| サンプル解読 | 架空の3例を画像から読み、1文字ずつ4本のバーと3つの隙間の幅を見る |
| 画像実験 | 同じ3例に5種類の加工を施し、既存の読取器で読み直して正解と比較する |
| 画像点検 | 自分の写真から、内容と開始・終了記号を読む |
| 座学 | 文字の構成・用途・チェック用文字・読み取りの限界を学ぶ |
| 確認問題 | 7問の選択問題と解説。答え合わせ・やり直しに対応 |

サンプルは数字、異なる開始・終了記号、数字と6記号の3例です。加工は、なし・上部の遮蔽・中央の細い横線・1文字の白塗り・バー全体の黒塗りです。結果はこの画像と読取器の組み合わせに限られます。
自由入力からのバーコード生成や手入力解読は未実装です。

## 🔄 PostMirrorとの違い

| 項目 | Codabar Lens | PostMirror |
|---|---|---|
| 対象 | NW-7（Codabar） | 日本郵便のカスタマバーコード |
| 表し方 | バーと隙間の細い幅・太い幅 | 高さと上下位置が異なる4種類のバー |
| 読み取る内容 | 数字と一部の記号。意味は発行者の運用による | 郵便番号と住所表示番号 |
| 主な学習 | 番号の符号化と画像からの読み取り | 住所情報の解読と隠し方の点検 |

NW-7は一般的な一次元バーコードの一種で、送り状や図書館などでも使われます。JANやCode 128とは別規格です。
NW-7と特定できても、その番号が追跡番号や顧客番号のどれに当たるかまでは分かりません。
カスタマバーコードを調べる場合は[PostMirror](https://ipusiron.github.io/postmirror/)を使ってください。

## 📖 使い方

まず「サンプル解読」で架空の例を選びます。「このサンプルを画像実験へ」で加工を比較できます。
自分の画像を使うときは「画像点検」タブで次の操作を行います。

1. 自分が扱ってよいラベルや資料の画像を選ぶ
2. 全体の画像で、いちばん左のバーといちばん右のバーを順にタップ
3. 拡大表示で左端・右端を選び直す。バーの中央の高さを選択
4. 表示された内容と前後の記号を確認し、印字されている文字と照合

タップは合計4回です。各バーを順に押す必要はありません。選択を間違えた場合は「1つ前に戻る」か「範囲を指定し直す」を使います。

## 🎯 ユースケース

このツールならではの使い方

- 逆から読むと別の文字になる組を数える（番号札・書体のデザイン）：ラベルを上下逆さにすると、バーの並びは逆順になる。「サンプル解読」の「数字と6種類の記号」（`C0123456789-$:/.+B`）で1文字ずつ幅の並びを見ると、内容に使う16文字は、並びを逆順にするとどれも別の1文字になる。組は0と3、1と8、2と9、4と7、5と6、`-`と`$`、`:`と`/`、`.`と`+`の8組である。前後の記号を除いた番号の部分だけなら、`123456`を逆から読むと`567098`になり、これも内容として使える並びである。逆順にした並びがどの文字にも当たらないのは、開始・終了記号のA〜Dの4文字だけである。読取器は両方の方向を試し、前後がA〜Dになる方向だけを採る。数字の札や球で6と9に下線を付けて上下を区別するのと同じ役目を、A〜Dが担っていることがわかる
- 読み取りの判定を多重化した装置の投票に見立てる（機械・制御の安全設計）：読取器は、選んだ範囲に沿って明るさを読む平行な線（走査線）を7本引き、3本以上が同じ文字列を読み、別の文字列を読んだ線が1本もないときだけ結果を出す。読めない線は4本まで許すが、7本のうち6本が同じ文字列を読んでも、残る1本が別の文字列なら結果を出さない。多数決ではなく、誤った値を出すより何も出さないほうを選ぶフェイルセーフの設計である。「画像実験」で「数字の例」（`A123456A`）に加工「中央に細い黒線を引く」を選ぶと、7本のうち4本がふさがれ、残る3本でちょうど条件を満たして読める。残る3本のうち1本をさらにふさぐと読めない
- 文字の区切りを調歩同期式の通信と比べる（電子工作・シリアル通信）：NW-7は1文字を4本のバーと3つの隙間の7要素で書き、文字と文字の間に区切りの隙間を置く。読取器は7要素ずつ数えて文字を切り出し、区切りの隙間は文字に含めない。`A123456A`の区切りの隙間をすべて細い隙間の3倍に広げても、1倍と3倍を交互に並べても、結果は`123456`のままである。5倍に広げた隙間は、この読取器では受け付けない（サンプルと同じく細い幅3ピクセル・太い幅6ピクセルで、区切りだけを広げた画像を描けば、「画像点検」で試せる）。この切り出し方は、スタートビットのあとの決まった数のビットを1文字として受け取る調歩同期式のシリアル通信（UARTなど）と同じであることがわかる。ただし、文字と文字の間の空き時間を問わないUARTと違い、この読取器は区切りの幅に上限を設けている

一般的な使い方

- 架空の`A123456A`を例に、内容の`123456`と前後の`A`を区別する
- 開始と終了が異なる`A12B`も形式として扱えることを知る
- 同じ高さの線でも、NW-7とJAN・Code 128では規則が異なることを比較する
- 自分の資料の番号が写真から読めるかを確かめ、写真を共有するときの見直しに使う

## ⚠️ 対応範囲と限界

- 内容は2〜80文字。数字0〜9と`- $ : / . +`、開始・終了記号A〜Dに対応
- 任意のチェック用文字が付いているかを自動判断せず、そのまま表示。用途固有の検算はしない
- バーコード全体の自動検出、遠近補正、HEIC、カメラ撮影、JAN・Code 128・ITF・QRコードは未対応
- 範囲指定にはタップまたはクリックが必要。キーボードだけの範囲指定は未対応
- 読めない文字を推測して部分結果を埋めない。失敗した場合は内容を表示しない
- 読めなかった結果は、ほかの方法でも読めないことを意味しない
- 住所・氏名・配送状況の照会、画像や結果の保存・共有は行わない

## 🔒 画像とデータの扱い

画像は端末内で処理し、外部に送信しません。画像点検から座学へ移ると画像と結果を消します。
16,777,216画素を超える画像は、その画素数以下へ縮小して扱います。言語設定だけを`localStorage`に保存します。
CDN・外部フォント・外部ライブラリへの実行時依存はありません。外部リンクを押した場合は、そのリンク先へ移ります。
